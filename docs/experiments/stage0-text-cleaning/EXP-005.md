# EXP-005 Protected UI Asset Preservation

## 目的

验证 Image-2 在执行文字清除时，右上角非目标功能图标丢失的问题，
是否能够通过更明确的 protected asset preservation Prompt 得到改善。

本实验不继续测试新的 mask 形式，也不改变文字删除区域。

核心问题：

> 当待删除文字位于小型 UI icon 附近时，
> Image-2 是否会在重绘过程中误删、简化或改变本不应该修改的 icon？

当前已知案例：

右上角：

- `12345/12345` 属于待删除 UI 数字文本；
- 其左侧黄色闪电图标属于需要保留的功能 icon；
- repair guide / mask 没有覆盖黄色闪电 icon；
- 但 EXP-001、EXP-002、EXP-003 的生成结果中，
  黄色闪电 icon 均出现丢失。

因此该现象目前更像是 Image-2 编辑过程中的
non-target asset preservation 问题，
而不是单纯的 mask 覆盖错误。

---

## 背景

此前完成：

EXP-001：
Baseline
原图 + 红色 repair guide + 原始 Prompt

EXP-002：
原图 + 红色 repair guide + Strong Text Removal Prompt

EXP-003：
改变 repair-region 表达方式

前三个实验均观察到：

右上角待删除数字附近的黄色闪电 icon 消失。

由于该现象从 EXP-001 即已经存在，
因此不能认为它是 EXP-002 强化 Prompt 新引入的问题。

当前需要单独验证：

是否通过显式声明“小型功能 icon 为 protected UI asset”，
可以提高 Image-2 对非目标 UI 元素的保真能力。

---

## 假设

如果黄色闪电 icon 消失的主要原因是：

Image-2 在进行全图 restoration 时，
将尺寸较小、位于边缘、靠近文字的功能 icon
视为可以简化、忽略或重新解释的视觉元素，

那么：

在 Prompt 中显式声明这些元素为 protected UI assets，
并明确禁止：

- remove
- omit
- simplify
- replace
- alter
- merge into repaired background

应该能够降低该 icon 被误删的概率。

如果加入强保护约束后仍然稳定丢失，
则说明单纯 Prompt preservation constraint 不足，
后续需要考虑：

- 局部编辑
- protected-region 输入
- source preprocessing
- 或其他工程级保真约束

## 本次唯一主要变量

只修改 Image-2 Prompt 中的
non-target UI asset preservation constraint。

不改变：

- source
- mask
- VLM
- OCR
- repair region
- model
- size
- generation workflow

---

## Prompt

使用当前实验所采用的 SOURCE_PLUS_OVERLAY_PROMPT，
在其中加入以下 protected asset constraint。

```text
NON-TARGET UI PRESERVATION IS A STRICT REQUIREMENT.

Only the ordinary UI text inside the indicated repair regions should be removed.

All non-text UI elements must remain present and visually unchanged.

Small functional UI icons are protected assets.

This especially includes:
- small utility icons
- resource icons
- currency icons
- energy icons
- lightning or bolt symbols
- circular control icons
- corner buttons
- navigation icons
- item icons
- decorative symbols that are not ordinary UI text

Do NOT remove, omit, hide, simplify, replace, reinterpret, merge, blur,
or redraw these protected non-text UI elements.

A protected icon must remain even when it is:
- very small
- located near removable text
- located inside or beside a text counter
- positioned near the edge or corner of the screen
- visually secondary to the main interface

Text removal must NOT cause adjacent icons to disappear.

When a repair region contains both removable text and a non-text icon,
remove only the text.

Preserve the non-text icon in its original:
- position
- size
- shape
- orientation
- color
- outline
- lighting
- visual style

Do not reconstruct the surrounding surface over a protected icon.

The source image is the authority for all non-target visual content.

If an element exists in the source image and is not explicitly a text-removal
target, it must still exist in the final image.

In particular, preserve small resource and functional icons adjacent to
numeric counters.

Successful repair means:
the indicated ordinary UI text is removed,
while adjacent non-text UI icons remain intact.
