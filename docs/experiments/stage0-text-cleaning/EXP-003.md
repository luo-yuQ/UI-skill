# EXP-003 Binary Mask Input

## 目的

判断 red overlay 作为第二张普通 reference image 是否存在视觉歧义。与 EXP-002 相比，只把第二张图从 red overlay 换成同一次 VLM pass 生成的 binary mask。

## 背景

`ui_image_clean_repair_poc.py` 并未调用 Image Edit mask API；`--mask-overlay` 始终上传一张普通参考图。因此 binary mask 在本实验中也是视觉说明图，而不是服务端 mask 字段。

## 假设

如果文字残留主要来自 red overlay 的视觉歧义，那么在 Prompt、source 和 VLM 区域完全不变时，binary mask 输入应比 EXP-002 更少保留 `999`、`12345/12345`。

## 固定条件

- source image：复用 EXP-001 的 `shared/source.png`
- OCR result：复用 EXP-001
- VLM result：复用 EXP-001
- 区域几何：复用 EXP-001 同一次 VLM pass 的 `region-mask.png`
- strong Prompt：逐字节复用 EXP-002 的 `strong-clean-repair-v2.txt`
- Image-2 model：`gpt-image-2`
- Image-2 size：与 EXP-001/002 使用相同自动映射规则
- 其他 Image-2 CLI 参数：保持默认值

## 本次变量

唯一主要变量：

```text
第二张普通 reference image：region-mask-overlay.png
→ region-mask.png
```

## 输入文件

- `runs/stage0-text-cleaning/shared/source.png`：固定 source。
- `runs/stage0-text-cleaning/exp-001/regions/region-mask.png`：与 EXP-001 red overlay 完全配对的 binary mask。
- `runs/stage0-text-cleaning/shared/strong-clean-repair-v2.txt`：复用 EXP-002；当前缺少。

## CLI

本实验复用 EXP-001 的 OCR、VLM 和 paired binary mask，因此不重新执行 OCR / VLM。

Step 1：确认复用文件存在

```powershell
Get-Item `
  "runs/stage0-text-cleaning/shared/source.png", `
  "runs/stage0-text-cleaning/shared/strong-clean-repair-v2.txt", `
  "runs/stage0-text-cleaning/exp-001/regions/region-mask.png"
```

Step 2：Image-2 binary mask reference

```powershell
python game-ui-asset-extractor/scripts/ui_image_clean_repair_poc.py `
  --image "runs/stage0-text-cleaning/shared/source.png" `
  --mask-overlay "runs/stage0-text-cleaning/exp-001/regions/region-mask.png" `
  --prompt-file "runs/stage0-text-cleaning/shared/strong-clean-repair-v2.txt" `
  --model "gpt-image-2" `
  --output-dir "runs/stage0-text-cleaning/exp-003/image2"
```

CLI 已存在且支持上传该文件，但 strong Prompt v2 和 EXP-001 输入/产物当前不存在。参数名仍叫 `--mask-overlay`，不改变其“第二张普通 reference image”的协议语义。
