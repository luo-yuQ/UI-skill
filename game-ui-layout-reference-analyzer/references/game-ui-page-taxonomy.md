# 游戏 UI 页面类型词汇表

优先使用下表稳定 ID，但不要为了命中词汇表而强行精确分类。证据不足时使用 `unknown`；多个同等重要的页面职能并存且无法确定主职能时使用 `hybrid`。

| 稳定 ID | 中文说明 | 常见页面目的 | 与相近类型的区别 | 常见误判提醒 |
| --- | --- | --- | --- | --- |
| `login` | 登录/进入页 | 身份进入、服务器选择或开始会话 | 与 `home` 区别在于尚未进入主要功能枢纽 | 单个“开始”按钮不必然代表登录页 |
| `home` | 主界面 | 展示核心入口、资源状态和主循环起点 | 比 `lobby` 更偏长期功能枢纽 | 不要把所有带导航的页面都归为主界面 |
| `lobby` | 大厅 | 组织多人、模式或房间入口并等待下一步 | 比 `home` 更强调进入对局前的聚集状态 | 不要仅因有角色展示就判断为大厅 |
| `hero_selection` | 英雄选择页 | 浏览并选择可用英雄/角色 | 与 `character_development` 区别在于目标是选择而非培养 | 详情页中的角色切换不一定是英雄选择 |
| `character_development` | 角色养成页 | 升级、装备、技能或属性管理 | 强调长期成长，不是临时编队 | 仅显示属性不代表存在养成功能 |
| `inventory` | 背包/库存页 | 浏览、筛选和管理持有物品 | 与 `shop` 区别在于对象通常已经持有 | 看到物品网格时先检查是否有价格或购买语境 |
| `shop` | 商城页 | 浏览商品、价格与购买入口 | 与 `inventory` 区别在于获取/购买是主任务 | 资源数量本身不能证明页面是商城 |
| `quest` | 任务页 | 查看任务目标、进度和奖励 | 与 `event` 区别在于围绕可执行目标组织 | 有进度条的页面不一定是任务页 |
| `event` | 活动页 | 展示限时主题、阶段或活动奖励 | 往往带时间性与专题结构 | 不要根据华丽装饰直接判定活动页 |
| `gacha` | 抽取页 | 展示抽取池、概率入口或抽取操作 | 与 `shop` 区别在于结果通常具有随机性 | 没有明确抽取证据时不要仅凭角色展示判断 |
| `mail` | 邮件页 | 浏览消息、附件和领取状态 | 与 `social` 区别在于以系统/玩家消息条目为主 | 通知列表不一定是邮件 |
| `ranking` | 排行页 | 比较名次、分数和玩家/队伍 | 强调有序排名而非普通列表 | 只有数字列表但无排名语义时需谨慎 |
| `social` | 社交页 | 好友、聊天、关注或玩家关系管理 | 与 `guild` 区别在于不围绕固定组织 | 头像列表不等于好友列表 |
| `guild` | 公会页 | 管理组织成员、活动与贡献 | 比 `social` 更强调固定群体和组织功能 | 排名或成员列表单独出现不能证明是公会页 |
| `matchmaking` | 匹配页 | 选择匹配条件、等待或取消匹配 | 与 `team_formation` 区别在于重点是寻找对局/对手 | 仅有确认按钮不代表匹配流程 |
| `team_formation` | 编队页 | 选择成员、位置或阵容并确认 | 与 `hero_selection` 区别在于组合多个对象形成队伍 | 单角色选择页不要误归为编队 |
| `battle_hud` | 战斗 HUD | 在实时玩法中显示状态与操作 | 与全屏管理页区别在于底层游戏场景仍是主要内容 | 带状态条的静态结果页不是 HUD |
| `battle_pause` | 战斗暂停页 | 暂停实时玩法并提供继续、设置或退出 | 通常覆盖在战斗画面之上 | 普通设置弹窗不一定是暂停页 |
| `battle_result` | 战斗结果页 | 总结胜负、奖励、统计与后续操作 | 与 `ranking` 区别在于总结单次对局 | 奖励弹窗不一定是完整结果页 |
| `settings` | 设置页 | 调整音频、画面、控制或账户选项 | 以偏好配置为主 | 少量开关可能只是其他页面的局部筛选 |
| `tutorial` | 教学引导页 | 分步解释操作并突出当前目标 | 通常带遮罩、指示或引导文本 | 单个提示气泡不一定构成教程页 |
| `modal` | 通用弹窗 | 在当前页面上完成确认、告知或短任务 | 表示呈现形态和局部任务，不代替更明确的业务类型 | 能判断具体职能时优先使用具体类型 |
| `unknown` | 未知页面 | 记录无法可靠确定的页面用途 | 明确表示证据不足 | 不要用低置信度的具体类型替代未知 |
| `hybrid` | 混合页面 | 表达多个同等重要且并存的页面职能 | 只有在无法选出主要职能时使用 | 不要把包含多个区域的普通页面都称为混合页 |

页面分类是分析标签，不代表路由名、引擎场景或实现类名。若使用 `unknown` 或 `hybrid`，在 `page_purpose` 和 `notes` 中说明依据与限制。
