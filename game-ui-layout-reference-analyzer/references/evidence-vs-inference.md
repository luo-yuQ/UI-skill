# 截图证据、推断与不确定性

所有交互关系、控制关系和功能判断都必须标注 `evidence_level` 与 `confidence`。置信度只表示当前证据强度，不表示事实概率经过统计校准。

## `observed`

仅用于截图中可直接看见、无需假设交互或业务含义的内容。

示例：

> 底部中央有一个面积较大的高亮矩形区域，其中包含文字。

可观察事实包括位置、相对大小、可见数量、颜色对比、层叠遮挡和明确可读的界面标签。即使文字看起来像操作词，也应把“可见文字”与“点击后的行为”分开描述。

## `inferred`

用于基于可见布局与常见 UI 规律得到、但截图没有直接证明的合理判断。

示例：

> 该高亮区域很可能是页面的主要操作按钮。

推断必须说明可见依据，使用“可能”“推测”等限定语，并降低置信度。区域控制、列表可滚动、选中项更新详情等关系通常属于推断，除非截图中存在明确状态或连线证据。

## `uncertain`

用于存在多种同样合理解释、图像模糊、被遮挡、被裁切或缺少状态对照的内容。

示例：

> 无法确认该图标是帮助入口还是信息说明入口。

把不确定项写入 `uncertainties`，说明受影响实体、原因与保守处理方法。不要用精确数字或确定语气填补证据缺口。

## 禁止的证据跃迁

除非截图中有足够直接证据，不得断言：

> 点击该按钮会花费 100 钻石并进入匹配。

不要把以下内容标为 `observed`：

- 点击结果、网络请求或页面跳转；
- 被裁切列表的完整总量；
- 图标背后的业务规则；
- 角色、货币或品牌元素可被直接复用；
- 仅由用户关注说明提供、但与画面冲突的事实。

## 置信度建议

- `0.85` 到 `1.0`：清晰、直接、无明显歧义的观察。
- `0.6` 到 `< 0.85`：证据较强或常规推断，但仍存在替代解释。
- `0.3` 到 `< 0.6`：有限证据支持的推断。
- `0` 到 `< 0.3`：高度不确定；通常应进入 `uncertainties`。

这些区间是表达一致性的建议，不得为了显得精确而虚构小数差异。
