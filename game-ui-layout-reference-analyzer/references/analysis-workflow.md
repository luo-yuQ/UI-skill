# A1 布局参考分析工作流

始终先分析整页和一级区域，再分析小控件。目标是得到可审查的结构化初稿，不是进行像素检测、素材提取或引擎实现。

## 1. 输入检查

1. 确认存在可读取的截图；没有可访问图片时停止并说明原因。
2. 判断截图是否为完整或接近完整的 UI 页面。单个图标、按钮、立绘或背景素材不适用。
3. 记录方向、大致宽高比，以及调用方提供的宽高。
4. 检查裁切、遮挡、模糊、系统状态栏、设备边框和水印。
5. 将限制写入 `source.capture_limitations`。图片不完美不等于必须拒绝；只要仍可识别主要页面结构，就继续并降低相关置信度。
6. 对照用户关注说明。若说明与画面冲突，以截图证据为准，并在 `notes` 或 `uncertainties` 中记录冲突。

## 2. 整页分析

先判断页面主要用途、当前状态、主任务和呈现方式：全屏页、弹窗、HUD、混合形态或未知。按需读取 `game-ui-page-taxonomy.md`，选择最合适的稳定 `page_type`；无法可靠归类时使用 `unknown`，多个同等重要职能并存时使用 `hybrid`。

不要因为局部存在商品卡、角色或按钮，就跳过整页任务判断。

## 3. 一级区域划分

按需读取 `layout-region-taxonomy.md`。按功能职责、空间连续性和与主任务的关系划分大区域，不要把每个视觉边框都当作 region。

常见整页结构可能包括：

- 顶部资源状态区；
- 左侧导航或筛选区；
- 中央对象列表区；
- 右侧详情或角色展示区；
- 底部主要操作区。

先覆盖大面积区域，再处理局部悬浮内容。为每个区域给出粗略归一化边界、z-order、证据级别和置信度。

## 4. 区域关系

检查 `parent-child`、`controls`、`updates`、`belongs-to`、`overlays`、`adjacent-to` 和 `repeated-within`。空间相邻可直接观察；控制、更新和交互关系通常需要推断。每条关系都要写出依据、证据级别和置信度。

不要为了连接所有区域而制造关系。父子引用必须存在，且不得形成循环。

## 5. 组件组

按需读取 `component-group-taxonomy.md`，在各 region 内识别标签组、卡片列表、资源组、奖励组、操作组、详情面板、角色展示、筛选组等逻辑组合。

保持在“区域之下、单控件之上”的粒度：

- 不逐个罗列文字、边框和小图标；
- 不把一个按钮拆成图标、底板和文字三个 group；
- 不把互不相关的相邻控件强行合并；
- 不输出引擎节点或组件类名。

## 6. 重复结构

1. 只在项目可清楚区分时填写明确 `visible_item_count`。
2. 被遮挡、模糊或裁切时使用 `null`，或用 `at_least` 表达最低可见数量。
3. 区分当前可见数量与推测的可滚动列表总量；A1 不填写看不见的总量。
4. 记录行、列、网格、轮播或列表方向。
5. 不把背景装饰的重复纹样当作 UI 重复组件。

## 7. 视觉层级

识别：

- 主要视觉焦点；
- 次级视觉焦点；
- 主要操作；
- 支持主任务的信息；
- 背景和装饰内容。

使用 region 或 component group ID 作为实体引用。无法可靠判断主操作时使用 `null`，不要根据颜色单一线索强行断言。

## 8. 区分事实、推断和不确定项

按需读取 `evidence-vs-inference.md`。把直接可见内容标记为 `observed`，把有可见依据的功能判断标记为 `inferred`，把多解或证据不足内容标记为 `uncertain`。所有功能、控制和交互结论都携带证据级别与置信度。

## 9. 提取可参考布局规则

从已记录的区域、关系和组件组提取抽象规则，例如：

- 左侧分类控制中央内容列表；
- 选中对象在右侧以更大尺度展示；
- 主要操作固定在详情区底部。

每条规则引用其来源实体，说明对原创 UI 的复用价值。规则只描述结构、比例、密度、层级和空间节奏，不要求复制具体画面。

## 10. 隔离品牌和具体内容

按需读取 `brand-isolation-guidelines.md`。保留可迁移布局知识，把游戏名、Logo、角色形象与轮廓、具体图标、货币造型、原始文案、独有纹样和品牌色组合写入 `excluded_content`。不要给出法律结论。

## 11. 自检

生成 JSON 前检查：

- 是否遗漏大面积功能区域；
- 是否只罗列小图标而没有页面结构；
- 是否把背景装饰当成按钮或重复组件；
- 是否把一个按钮拆成多个逻辑组；
- 是否把多个独立组件误合并；
- 是否混淆截图事实与功能推断；
- 数量是否来自可见证据；
- 所有 ID 和引用是否一致；
- 是否包含切图、九宫格、图片 API、生成提示词或引擎内容。

## 12. 输出与校验

按需读取 `output-contract.md`，生成符合 `../schemas/layout-reference-analysis.schema.json` 的 `layout-reference-analysis.draft.json`。运行 `../scripts/validate_layout_reference_analysis.py <analysis-json>`。

validator 失败时，根据错误修正 JSON 并重新校验。不得把非法 JSON 交给 A2 或其他下游。
